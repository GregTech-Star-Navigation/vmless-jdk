## 1. 要做什么

让解释器能跑**真的反射**：`java.lang.Class` 的成员查询、`Field`/`Method`/`Constructor`
的读写与调用、运行期注解（含默认值）、泛型签名的 `Type` 对象。这是「跑 Minecraft」的
四块硬骨头之一 —— FML 的 `@Mod` 扫描、Jackson 的属性绑定全压在它上面。

四条线，按顺序：

- **A `Class` 的反射入口**：`forName`（含数组名与基本类型）、`getDeclaredFields/Methods/
  Constructors`、`getFields/Methods/Constructors`、按名字精确匹配（含可变参数）、
  `getSuperclass`/`getInterfaces`/`isAssignableFrom`/`isInstance`/`cast`、
  `getModifiers`/`isInterface`/`isArray`/`isPrimitive`/`getComponentType`、
  `getSimpleName`/`getCanonicalName`/`getName`（按 JLS 的口径）。
- **B 反射对象**：`Field.get/set` 全族（8 种基本类型 + Object）、`setAccessible`（要在
  `private` 上真生效）、`Method.invoke`（拆装箱 / 宽化 / `null` / 可变参数）、
  `Constructor.newInstance`、异常语义（`NoSuchField/MethodException`、
  `IllegalAccessException`、`InvocationTargetException` 包装）。
- **C 运行期注解**：解 `RuntimeVisibleAnnotations` / `RuntimeVisibleParameterAnnotations`
  / `AnnotationDefault`；`getAnnotation`/`getAnnotations`/`isAnnotationPresent`；
  注解实例的成员方法取值（含默认值）。
- **D 泛型签名**：`getGenericType`/`getGenericReturnType`/`getGenericParameterTypes`，
  最小集 `ParameterizedType` / `TypeVariable` / `GenericArrayType` / `WildcardType`。

## 2. 不做什么

- **不做 `java.lang.reflect.Proxy` 与运行期字节码生成**：真 HotSpot 的注解实例是
  `Proxy` 子类，靠 `ProxyGenerator` 现生成 class 文件。本 VM 没有「运行期生成字节码」，
  所以注解实例是「运行时类 = 注解接口 + 成员值放在 `Vm::ann_objs` 里」的代理对象，
  成员方法在 `ann_objs` 上查表（与 lambda 对象同一套手法）。
- **不做模块系统与 `SecurityManager`**：访问检查只按「`setAccessible(true)` / public /
  同一个嵌套宿主」三条判，`Module.isExported` 那条链不接（`InaccessibleObjectException`
  也不会出现）。
- **不做 `Proxy` 之外的注解扩展**：`getAnnotationsByType`（可重复注解）、
  `AnnotatedType`、类型注解（`RuntimeVisibleTypeAnnotations`）都不做；
  `getDeclaredAnnotations` 与 `getAnnotations` 同义（不做 `@Inherited` 的继承查找）。
- **不做调用栈模型**：`Throwable` 的栈轨迹仍为空，`Reflection.getCallerClass()` 仍返回
  `Object.class`。
- **不改 JIT 侧**：JIT 不支持 `ACC_NATIVE` 之外的反射，遇到反射调用点自然退回解释器
  （现状即如此，本 REQ 不动它）。
- **不动 `repo/`、`dllwork/`、`jdk-*/`、`merge/`、`jbcov/`、`jdkapi/`**（其它子代理的目录）。

## 3. 已知约束

- `java.lang.reflect.Field` 的构造器**声明**是
  `(Class, String, Class, int slot, boolean trustedFinal, int modifiers, String signature, byte[])`，
  但构造器体里写的槽是 `modifiers ← 4`、`trustedFinal ← 5`、`slot ← 6`
  （只有 `javap -c` 才看得出来）。按声明顺序传会把 `modifiers` 和 `slot` 对调：
  表现是 `getModifiers()` 恒 0、`getInt()` 读到别的字段。
- `Class.getModifiers()` 的口径：数组 = 元素的 PUBLIC/PRIVATE/PROTECTED + ABSTRACT + FINAL；
  基本类型 = PUBLIC + ABSTRACT + FINAL；成员类（`Outer$Inner`）的 `static`/`private` 等
  **不在**自己 class 文件的 `access_flags` 里，要并上 `InnerClasses` 属性那一项；
  `ACC_SUPER`(0x0020) 不是 Java 修饰符，必须摘掉（否则 `Modifier.toString` 多一个
  `synchronized`）。
- `java.util.StringJoiner.toString()` 是 `JLA.join(...)`，而 `JLA` 由
  `System.initPhase1()` 挂上（HotSpot 里由**启动器**调用，不是字节码）。本 VM 不走
  `initPhase1`（会把 `Properties`/`FileInputStream` 一整条链拖进来），所以这一条按语义
  由 VM 直接给。`Modifier.toString` 正是它的用户。
- 注解 `toString()` 的成员顺序 = `AnnotationType.memberDefaults`（一个 `HashMap`）的
  迭代顺序，而它按 `Class.getDeclaredMethods()` 的顺序插入 —— HotSpot 会**重排**方法表，
  所以「多个带默认值成员」的注解 `toString` 顺序无法逐字符复现（见 §6）。
- 泛型签名**不需要自己解析**：把 `Signature` 属性填进 `Field/Method/Class` 的 `signature`
  字段后，`sun.reflect.generics.*` 那套 java.base 字节码自己就解析出来了 ——
  前提是 `System.arraycopy` 允许 `Object[] ← TypeVariable[]` 这种**元素类型不同**的复制
  （以前一律拒绝，连泛型签名都过不去）。

## 4. 方案（要点）

1. **native 与 override 分开登记**（判据同 `native_reg.rs` 的头注释）：
   `forName0` / `getDeclared*0` / `getInterfaces0` / `getDeclaringClass0` /
   `getSimpleBinaryName0` / `getGenericSignature0` 在 OpenJDK 里本来就是 `native`；
   `getDeclaredFields` 一族、`Field.get/set` 一族、`Method.invoke`、
   `Constructor.newInstance`、`getAnnotation` 一族是**字节码但语义必须由 VM 给**，
   走 `overrides` 表（`is_override_owner` 里加上这几个类名，热路径仍是「类名不分配比较」）。
2. **反射对象就是真对象**：`Field`/`Method`/`Constructor` 用它们自己的构造器造出来，
   `clazz` / `slot` / `name` / `type` / `modifiers` / `signature` / `parameterTypes` 全部填好。
   于是 `getName()` `getModifiers()` `getType()` `equals` `toString` `Modifier.toString`
   这些**纯字节码方法一行都不用写**（`slot` = 成员在自己那张表里的下标，`clazz` = 声明类）。
3. **注解代理**：对象运行时类 = 注解接口，成员值表在 `Vm::ann_objs`；
   `invokeinterface` 里在解析之前先问 `ann_dispatch`（与 `lambda_dispatch` 同一层），
   命中就按名字返回值。成员顺序按「默认值（HashMap 序）+ 显式值追加」合并。
4. **运行期类加载**：`Vm::open` 现在留着 `ClassPath`；`Class.forName` 与新造对象时
   走 `ClassStore::load_closure`（与启动时同一套闭包规则），找不到才报
   `ClassNotFoundException`。
5. **访问检查**：`override`（`AccessibleObject.override` 字段）→ 放行；public 成员 → 放行；
   否则要求「调用者与声明类同一个顶层类」。调用者用 `Vm::last_caller`（调用点写入的类下标）。
6. **泛型**：只填 `Signature` 字段，其余交给 java.base 的 `sun.reflect.generics`。

## 6. 不做 / 没做到的

- **注解 `toString()` 的成员顺序**：只对「≤1 个带默认值成员」的注解逐字节一致；多个默认值
  成员时我们按声明序的 HashMap 桶序打印，HotSpot 按它自己重排后的方法序插入 ——
  集合相同、顺序可能不同。`equals`/`hashCode` 不受影响（按 key 对齐比较）。
  验收里 R5 只断言 `toString` 的前缀与 `startsWith`，不断言整体顺序。
- `getAnnotationsByType`（可重复注解）、`AnnotatedType`、类型注解、`@Inherited` 的继承查找：
  未做（见 §2）。`getDeclaredAnnotations` 与 `getAnnotations` 同义。
- `Method.getParameters()`（`Parameter` 对象）未接管：`Executable.getParameters0` 仍是
  未注册的 native，取参数名会走到 `UnsatisfiedLinkError`。R6 只用
  `getParameterAnnotations`，不碰它。
- `java.lang.reflect.Proxy` / 动态代理类生成：未做（`Annotation` 之外的代理对象拿不到）。
- **顺手发现但没修**（超出本 REQ 边界，留给下一个人）：
  `src/vm/exec.rs` 的数组读写（`0x2e..0x35` / `0x4f..0x56`）**越界不抛异常**，
  静默返回 0 / 静默丢弃写入 —— `new int[0][0]` 那种空数组取元素应当抛
  `ArrayIndexOutOfBoundsException`（M15 里对比出来）。修它会改到 JIT / 三路一致的行为，
  所以单独一件活。
