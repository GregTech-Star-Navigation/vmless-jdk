# GC：解释器堆的标记-清扫回收（2026-11-18）

状态：可用（v0.58 之后的一次能力补充）。文件：`src/vm/gc.rs`（主体）、
`src/vm/shared.rs`（堆结构 / 标记位 / 清扫）、`src/vm/frame.rs`（帧带位图）`、
`src/vm/exec.rs`（接入点）。

## 一句话

解释器的对象堆原来**只增不减**（线性于累计分配量）。现在接上了**精确根**的标记-清扫：
8M 次分配 / 100 万存活的负载下，最大停顿 **12.5–13.6 ms**（G1 实测 12.74 ms），
2M 个短命对象下峰值 RSS 从 297 MB 降到 62 MB。

## 为什么是「标记-清扫 + 不搬动」

句柄就是页表下标（`>0` 对象 / `<0` 数组 / `>= STR_BASE` 字符串），页表里已发布的条目
**地址永不搬动** —— 这是「任何线程都能安全拿任意对象引用」的全部前提。搬动会让所有
句柄失效，所以：

- **不压缩**（要压缩得先做出句柄间接层，那是另一件事）；
- **索引不复用**：复用会让「还活在别处的陈旧句柄」指向另一台对象 —— 静默数据损坏，
  比多占一点页表内存糟得多。代价是累计分配量有个 3355 万的上限（页表用尽时报
  `OutOfMemoryError`，与改动前一样）。

## 精确根从哪来（这是整件事的拦路虎）

`Frame.locals` 是 `Vec<Slot>`，引用（句柄 i32）和 int 混在一起没有类型标签。追溯扫描
无法区分「句柄 5」和「整数 5」：把整数当引用 → 把随机下标当对象；漏掉真引用 → 活对象
被回收。所以每个方法在**第一次执行时**算一张 `pc → (哪些局部槽是引用, 哪些栈位是引用)`
的表（`gc::MethodRefs`），运行期帧带着它（`Frame.refs` + `Frame.pc`）。

- **来源**：字节码**数据流分析**（`gc::analyze`）—— 等价 JVM 校验器做的事，只是格简化成
  「引用 / 非引用 + 槽宽」：`aload` 压引用、`iload` 压 int、`invoke*` 看返回描述符、
  `getfield` 看字段描述符……跳转点用**并（OR）**合并（并 = 往「多标」方向走，安全）。
  比 `StackMapTable` 更细：`StackMapTable` 只在分支目标/异常入口给帧，这里**每条指令
  都有**。异常 handler 的局部变量取 try 范围内各指令状态的并（过近似，安全）。
- **退化**：不认识/对不上（`jsr/ret/wide`、栈深或宽窄不一致）→ 整个方法用**保守位图**
  （所有槽都当潜在引用，逐个用页表验证）。保守只会多留垃圾，不会漏根。
- 缓存在 `Shared.refmaps`（键是 `(Arc<ClassFile> 指针, 方法下标)`，连 `Arc<ClassFile>`
  一起存，指针不会被复用）。

**运行期兜底**（宁可漏回收，不能回收错）：

1. 帧的位图与当前栈深对不上 → 这一帧退回保守扫描（实际栈比位图短是合法的：停在调用点
   上时参数已经弹掉，剩下的正好是位图栈的前缀）。
2. **Rust 栈保守扫描**：解释器/native/反射/indy 在 Rust 局部变量里临时拿着一句柄的情况
   （异常对象在展开途中、indy 的临时值）靠它兜住。候选值一律过页表验证。
3. 共享冷表（静态字段、类对象表、字符串常量表、indy 状态、监视器表、线程表、包装类缓存…）
   按「表里出现的 i32 都可能是句柄」处理并验证 —— 表都很小，多标有界。
4. 每个线程的 `Vm.held`（持有但未膨胀的 thin 锁对象句柄）。

## 回收协议

- **只在解释器主循环的指令边界上回收**：`pc` 精确、栈形状与位图一致。分配函数自己
  **不**触发回收，只累加计数（否则 `pc` 会停在半条指令上，位图对不上）。
- 停世界沿用 `gc.rs` 原有的停靠点协议；**停不全就放弃这一轮**（4 ms 超时，失败后 50 ms
  内不再尝试）。每个线程各自宣告「我停在第几轮」，所以上一轮迟到的宣告不会被下一轮
  误当成「已到齐」。
- 标记：世代号 + 工作队列，**多线程**（默认 `min(核数, 8)`，`VMLESS_GC_THREADS` 可覆盖）。
  分配在 GC 期间发生的对象直接带「本轮已标记」的世代号。
- 清扫：**在暂停之外**做（就地做小堆，起后台线程做大堆）。清扫只释放「世代号 < 本轮」
  的条目，所以和新一轮标记不会打架（新标记会把活对象的世代号写到更新，清扫条件不成立）。
- 触发：`已分配数 >= max(存活数 × 2, 262144)`。

## 开关（都是环境变量）

| 变量 | 作用 |
| --- | --- |
| `VMLESS_GC_STATS=1` | 每次回收打一行：pause / live / 位图覆盖率；清扫另打一行 |
| `VMLESS_GC_STRESS=1` | 压力模式：每 64 条字节码检查一次，**只要这一小段分配过就回收**（把漏根立刻打成崩溃）。合并后用它复跑回归 |
| `VMLESS_GC_OFF=1` | 完全关掉回收（量「改前」基线用，其余行为不变） |
| `VMLESS_GC_VERIFY=1` | 每轮打印「精确 / 保守 / 位图失配」帧数 |
| `VMLESS_GC_THREADS=N` | 标记线程数 |
| `VMLESS_REFMAP_DEBUG=1` | 位图退化时打印原因（pc + 指令） |

## 已知边界（没做的）

- **索引不复用**（见上）：RSS 里仍有一项随累计分配量线性增长 —— 页表条目 8 字节/对象
  （1M/2M/4M 次分配实测 51/62/82 MB）。要彻底平，得做「空闲表 + 显式失效」或者句柄
  间接层。
- **没有增量/并发标记**：标记仍然是 stop-the-world，pause ∝ 存活对象数。
- 字符串堆（`STR_BASE` 以上的句柄）**不回收**：它们是不可变常量/驻留串。
- `exc_msgs` 等冷表会把异常对象一直留到表项被覆盖（改动前就有的行为）。
- 页表是按对象**下标**组织的一级/二级结构，标记每个对象至少一次页表查找 + 一次
  `ObjHdr` 访问；`ObjHdr.refs` 为 `None` 的对象跳过槽位数组（不碰第二次缓存行）是
  把停顿从 15.7 ms 压到 12.6 ms 的关键优化。

# 0.69.0：对象布局压缩 + 分代（写屏障 + 年轻代回收）

状态：可用。文件：`src/vm/shared.rs`（布局 / 分代状态 / 写屏障 / DirtyMap）、
`src/vm/gc.rs`（回收种类、标记器、清扫区间）。

## 实测（同机、5 次取中位并给区间，GcBench = 8M 分配 / 100 万存活）

| 指标 | 0.68 | 0.69 |
| --- | --- | --- |
| 峰值 RSS | 396.2 MB [395.4..397.2] | **166.8 MB [166.1..167.5]** |
| 最大单次停顿 | 16.81 ms [12.79..16.95] | **14.49 ms [13.58..14.79]** |
| 2M 短命对象峰值 RSS | 67.5 MB [65.6..68.0] | **32.8 MB [32.3..33.7]** |
| 1M/2M/4M 分配 RSS | 56.6 / 67.1 / 82.3 | **25.9 / 32.4 / 48.4** |
| 年轻代回收停顿 | —— | **3.3–3.8 ms**（与活集无关） |

## 对象头 56 B → 24 B

```text
     0        lock: AtomicU32         4
     4       epoch: AtomicU32         4
     8      nslots: u32               4
    12   class_id: u32                4     ← 旧布局是 Arc<str>（16 B）
    16        refs: u64               8     ← 旧布局是 Arc<RefBits>（8 B）+ 独立 Box<[Cell]>
    24  cells: [Cell; nslots]              ← 内联，同一次分配
```

- 类名：`u32 class_id` 查 `Heap::class_names`。分配热路径上只有一次
  `RwLock<HashMap<Box<str>, ClassMeta>>` 读 —— 与旧的 `obj_refbits` 读同一把锁等价。
- 引用位图：**一个 8 字节域两种解释**。`refs == 0` ⟺ 一个引用槽都没有（**唯一约定**，
  两种宽度同一套语义，`is_ref`/`has_refs` 都先判 0）；`nslots <= 64` 时是内联位图；
  `nslots > 64` 时是泄漏成静态实例的 `*const RefBits`。
  > 这个约定踩过一次线上事故：早期版本对「非引用数组且 `nslots > 64`」直接写 0，
  > 宽路径把 0 当指针解引用 → release 下直接 SIGSEGV（长字符串、大 `byte[]`、`ArrayList`
  > 全崩）。现在 `RefBits::to_word` 第一行就把 `None` 归一成 0。
- 槽位数组内联：一次 `std::alloc::alloc(24 + 16n)` 代替「头 Box + 槽位 Box」两次分配，
  少 16 字节 malloc 块头 + 8 字节指针，标记时也少一次跳跃（这是停顿的主要来路）。
  释放走 `free_obj`：`nslots` 只写一次，算布局靠读回来。

## 分代：写屏障 + 年轻代回收

- **年轻代下界**：`young_lo_obj` / `young_lo_arr` = 「上一次年轻代回收之后的分配下标」。
  下标 `>= 它` 就是年轻的。不做复制（不搬动），晋升 = 把下界推到当前末尾。
  所以**不需要额外的年代字段，也不需要复制/from-space**。
- **写屏障**：`set_ref` **和** `set`（按槽位位图判断）都记一笔。记的是
  「老对象里被写过引用」—— `DirtyMap`：1 bit 一个对象，按需分页（一页 26 万个对象）。
  不用卡表：卡表按地址分块，一块 512 个对象，回收时得整块扫；位图精确到对象。
  目标是不是年轻代**故意不判断**：多记一笔只是多扫一个对象，漏记就是把活对象回收掉。
- **年轻代回收**：STW → 收根 → 扫新生段 → 把脏老对象的引用槽当根 → 清扫 `[老下界, 本轮高水位)`
  → 晋升（下界 = 当前末尾）。**老年代的条目一个都不碰。**
- **扫槽时过滤老目标**（`scan_refs_young`）：脏老对象里绝大多数槽指向老对象，
  只比较一次下标就扔掉，省掉一次页表查找。这是把 GcBench 的 1M 槽 `keep` 数组
  从「每次年轻代回收 47ms」压到毫秒级的那一条。
- **eden 自适应**：8 MB 起步，存活率 ≥50% 翻倍、≤2% 减半，上限 96 MB。
  `los_bytes = eden/8`（G1 的 `G1HeapRegionSize` 思路），大对象的 eden 记账按它截断。
- **触发判据（字节口径）**：
  1. `young_bytes >= eden_bytes` → 年轻代回收；
  2. 自上次全量以来分配 ≥ `max(存活字节 × 1.5, 32MB)` → 全量回收；
  3. `VMLESS_GC_STRESS` → 交替做年轻代/全量（两条路径都要被漏根检测覆盖）。
  **第一次回收固定是全量**：冷启动时「下界之前都活着」这个前提还不成立。

## 并行标记的两个坑（都已修）

1. **并行判据不能共用一份 `last_marked`**：年轻代回收只标几千个对象，会把它写小，
   于是紧随其后的全量回收永远判成单线程。100 万活对象单线程 47ms、16 线程 13.7ms。
   现在全量看 `last_major_marked`。
2. **批次太小会锁竞争**：`MARK_BATCH` 1024→16384、`MARK_CHUNK` 32→512，实测标记
   18.2ms → 13.7ms。再往上加线程没用（8→32 线程只从 16.8 降到 13.3）—— 标记是
   **内存延迟/带宽受限**，不是线程数受限。

## 仍是已知边界

- **全量回收仍然 stop-the-world**，停顿 ∝ 活集（100 万活对象 ≈ 13.7ms）。
  增量化的完整设计（已想清，未实现）：`set_ref` 上做 incremental-update 屏障
  （目标对象 `epoch == 本轮` 时把它记进重扫集）；标记期间新分配的对象按
  `epoch - 1` 出生（视为未标记）；终局 STW 重扫根 + 重扫集。这样终局的工作量
  与活集成正比的部分被挪进 mutator 时间片，STW 只剩「扫根 + 脏集」。
- **索引不复用**：页表条目 8 字节/对象随累计分配量线性增长（8M 次分配 = 64 MB）。
  要彻底平得改 `i64` 句柄（`index32 + epoch32`，epoch 不符判 null），
  那会碰到 exec / JIT / native 全部调用点，本轮没动。
- 字符串堆（`STR_BASE` 以上）不回收。
