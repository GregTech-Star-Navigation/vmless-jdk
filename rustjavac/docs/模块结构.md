## 为什么 `lib.rs` 只有 re-export

拆完以后 `lib.rs` 一共 22 行：

```rust
pub mod classfile;
pub mod front;
pub mod sema;
pub mod lower;
pub mod codegen;
pub mod compiler;
pub mod vm;
pub mod jit;

pub use crate::classfile::{parse, write, Error, Result};
pub use crate::classfile::{java_double_to_string, ret_of};
pub use crate::classfile::{Attribute, ClassFile, CpEntry, Member};
pub use crate::front::{ast, lexer, parser};
```

两条理由：

1. **对外 API 一个字没变。** 拆模块最容易踩的坑是 `use classfile::parser::…` 全部失效。
   这里用 re-export 把旧路径原地保留（见下表），`examples/` 一个字符都不用改。
2. **以后再拆 `compiler.rs` / `vm.rs` 时，`lib.rs` 不需要再动。** 新增目录只要加一行 `pub mod`，
   其余模块通过 `crate::<类型名>` 的 re-export 继续工作。

因为 crate 名和模块名都叫 `classfile`，外部写 `classfile::parse` 命中的是 crate 根上的
re-export，而 `classfile::read::parse` 命中的是模块里的原件 —— 两者都通。
`classfile::write` 同时是模块名（类型命名空间）和函数名（值命名空间），Rust 允许，
调用位置自己决定取哪个。

## 旧路径对照表（公开 API 兼容性）

| 旧路径 | 现在实际位置 | 兼容方式 |
| --- | --- | --- |
| `classfile::parse` | `classfile::read::parse` | `lib.rs` re-export |
| `classfile::write` | `classfile::write::write` | `lib.rs` re-export |
| `classfile::Error` / `Result` | `classfile::mod` | `lib.rs` re-export |
| `classfile::ClassFile` / `CpEntry` / `Attribute` / `Member` | `classfile::mod` | `lib.rs` re-export |
| `classfile::ret_of` / `java_double_to_string` | `classfile::mod` | `lib.rs` re-export |
| `classfile::ast::*` | `front::ast` | `lib.rs` re-export 模块 |
| `classfile::lexer::*`（`Tok` / `Token` / `tokenize` / `KEYWORDS` / `LexError`） | `front::lexer`（+ `front::lexer::token`） | `lib.rs` re-export + `front/lexer/mod.rs` 里 `pub use token::*` |
| `classfile::parser::parse_compilation_unit` | `front::parser` | `lib.rs` re-export 模块 |
| `classfile::sema::*` | `sema`（`sema::symbols`） | `lib.rs` 直接 `pub mod sema` + `pub use symbols::*` |
| `classfile::lower::*` | `lower` | `lib.rs` 直接 `pub mod lower` |
| `classfile::codegen` / `compiler` / `vm` / `jit` | 未动 | 同上 |

`examples/` 里所有引用（`classfile::jit::compile_file`、`classfile::parser::parse_compilation_unit`、
`classfile::{lower, parser, sema}` …）都按原样工作。

## 这次只加了可见性，没有改语义

跨文件调用 `Parser` 的方法时需要 `pub(crate)`，所以：

- `front/parser/{mod,decl,stmt,expr}.rs` 里全部 `fn` 方法由私有改成 `pub(crate)`（46 个），
  签名、函数体一字未动；
- `classfile/read.rs` 的 `Reader` 结构与其 4 个原语方法由私有改成 `pub(crate)`
  （`attr.rs` 要用 `u16` / `u32` / `bytes`）；
- `classfile/{pool,attr}.rs` 的 `write_cp` / `read_attributes` / `write_attributes` 改成 `pub(crate)`。

除此之外，移动的行是逐字照抄的：把新文件里新增的行（模块文档、`pub mod`、`use`、`pub use`、
`pub(crate)` 前缀）剔除后，与原文件做多重集合比对 —— **丢失 0 行逻辑，新增 0 行逻辑**。

`impl Parser` 被拆成 4 个 impl 块（每文件一个）；Rust 允许同一个类型的多个 inherent impl。
`Parser` 的私有字段（`toks` / `pos` / `pending` / `line`）能被子模块直接访问，因为
`front/parser/{decl,stmt,expr}.rs` 是定义 `Parser` 的模块（`front/parser/mod.rs`）的后代。

## 已知遗留

1. `classfile::pool` 目前只有写回一半。读的一半仍内联在 `read::parse` 的 `while i < cp_count`
   循环里 —— 抽成 `read_cp_entry` 属于改动函数结构，本轮明确不做。
2. `parser/mod.rs` 的 `decl` / `stmt` / `expr` 三个子模块各开一个 `impl Parser`，
   方法实际仍是同一个类型的成员；将来若要按文法进一步拆，成本很低。
3. `codegen.rs` / `compiler.rs` / `vm.rs` / `jit.rs` 仍是单文件（合计 5678 行），下一轮处理。
