# 接口

> 对外契约：39 个 exe 的命令行、VM 的运行时开关、退出码约定。
> 更新：2026-11-18。退出码细节另见 [工具退出码.md](工具退出码.md)，体积见 [工具体积.md](工具体积.md)。

## 核心三个入口

### `javac.exe`（自研编译器）

```
javac <选项> <源文件.java>
```

| 选项 | 说明 |
| --- | --- |
| `-d <目录>` | 输出 `.class` 的根目录（按包名建子目录） |
| `-cp <路径>` / `-classpath <路径>` | 类路径（`;` 或 `:` 分隔）。**跨编译单元解析全靠它** |
| `-encoding <名字>` | 源码编码，默认 UTF-8 |
| `--help` | 用法 |

产出是**标准字节码**（真 JVM 能加载）。但有两处已知偏差：
访问修饰符一律写成 `public`；循环回边上的局部变量帧未做路径合并（真 JVM `-Xverify:all` 可能拒载）。

### `java.exe` / `rustjava.exe`（VM）

三种入口形态：

```
java <文件.class>                 # 单文件
java -cp <路径> <主类名>           # 类路径 + 主类（按包名用 / 或 .）
java -jar <文件.jar>              # 可执行 jar（读 MANIFEST 的 Main-Class）
```

| 选项 | 说明 |
| --- | --- |
| `-cp` / `-classpath` | 目录 / jar / jimage 混排，按序查找 |
| `-jar` | 与 `-cp` 互斥 |
| `-D<键>=<值>` | 系统属性（进 `System.getProperties()`） |
| `-m` / `--module` | JPMS 模块方式运行 |
| `-p` / `--module-path` | 模块路径 |
| `--add-opens` / `--add-exports` / `--add-reads` / `--add-modules` / `--limit-modules` | 与真 JDK 语义一致 |
| `--describe-module <模块>` | 打印模块描述（70 个模块内容全对） |
| `--print-module-resolution` | 打印解析后的模块图 |

**退出码**：正常返回 `main` 的退出值（`System.exit(n)` 亦同）；未捕获异常 → `1`；
VM 自身错误（类找不到 / 字节码不支持）→ `1` 并在 stderr 说明。

### `run_jdk.exe`（跑真 `java.base` 字节码）

```
VMLESS_JDK=<lib/modules 或解包目录> run_jdk <类目录> <主类名>
```

这是**验收与调试专用**的入口：加载真 OpenJDK 的 `java.base`（7350 个类）并执行。
普通用户走 `java.exe` 即可。

## 运行时开关（环境变量）

| 变量 | 作用 | 什么时候用 |
| --- | --- | --- |
| `VMLESS_JDK` | `java.base` 的类来源 | 跑真实库代码必须设 |
| `VMLESS_GC_STATS=1` | 打 GC 停顿/回收统计 | 量内存行为 |
| `VMLESS_GC_STRESS=1` | 每次分配都 GC | **漏根检测**，验收必跑 |
| `VMLESS_GC_OFF=1` | 关回收 | 量「改前」基线 |
| `VMLESS_GC_VERIFY=1` | 位图校验 | 查引用位图是否正确 |
| `VMLESS_GC_THREADS=<n>` | 并行标记线程数 | 量停顿构成 |
| `VMLESS_GC_REFMAP_DEBUG=1` | 打位图分析细节 | 查保守退化的原因 |
| `VMLESS_HANG_DUMP=<秒>` | 卡死探针，每约 1600 万条指令打一次「当前 类.方法@pc」 | **排查死循环/挂死** |
| `VMLESS_JIT_NO_INLINE=1` | 关 JIT 内联 | 二分定位（开/关输出必须一致） |
| `VMLESS_DIVMOD_FULL=1` | 除余魔数全量穷举自检 | 改 `divmod.rs` 后跑 |
| `VMLESS_TRACE=1` | 每条字节码一行 | 只在极小样例上用（几秒刷爆屏） |
| `VMLESS_INDY_STATS=1` | 打 `invokedynamic` 调用点缓存命中 | 查 indy |
| `VMLESS_AWT_TRACE=1` | 打 AWT native 进出 | 查 `java.desktop` |
| `VMLESS_NAT_TRACE=1` | 打 native 关键节点 | 查 native 层 |

## 工具（其余 36 个）

行为与真 JDK 同名工具一致（`--help` 都有）。**已双向互通验过的**：

| 工具 | 互通证据 |
| --- | --- |
| `jimage` | `extract` 与真 `jimage` **逐字节相同**；全量 30482 条目 |
| `jmod` | 真 JDK 能 `list`/`describe`/`extract` 我们做的 jmod |
| `serialver` | 20 个 `java.*` 类的 `serialVersionUID` 与真 serialver 全一致 |
| `jarsigner` | 我们签的 jar **真 jarsigner 验得过**（`jar verified.`）；反向也通 |
| `keytool` | 真 `keytool -printcert` 读得懂我们的 DER；PKCS#12 **双向**可读 |
| `kinit`/`klist`/`kdc` | **真 JDK 25 的 `kinit` 能登进我们的 KDC** |
| `jfr`/`jhsdb` | 真 `jfr summary/print` 读我们写的 `.jfr`，204 行逐字节相同 |
| `jps`/`jstat`/`jcmd`/`jinfo`/`jmap`/`jstack` | perfdata 用 **HotSpot v2.0 二进制格式** → **真 `jps`/`jstat` 能直接读我们的 VM** |

**不支持 / 只到某一层的**：

| 工具 | 边界 |
| --- | --- |
| `jpackage` | `app-image` 真实现；`exe`/`msi` 明确报边界 |
| `jdb` | 基础断点/单步；**没有帧栈模型**，`where` 给不出帧 |
| `jshell` | 编译 + VM，变量保留；不是真 JShell 的完整 REPL |
| `jhsdb` | 读 `.jfr` 的栈信息；不是真 debug server |
| `rmiregistry` | 最小实现 |

## 版本约定

- `rustjavac/Cargo.toml` 的 `version` 是**唯一真相源**，打包脚本按它取版本
- `CHANGELOG.md` 每次能力变更加一节；纯文档/测试/重构不加
- 修 bug → patch 位；加能力 → minor 位；不兼容的配置格式变更 → major 位
