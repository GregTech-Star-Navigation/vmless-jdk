## 能用的

### 执行真实字节码
- **类来源**：目录树 / `jar` / 真 `jimage`（`lib/modules`，自己解二进制格式，不是目录回退）
- **JPMS**：70 个模块的 `describe` 内容全对；`--add-opens` / `--add-exports` / `-m` 行为与真 JDK 一致
- **反射 + 运行期注解**：`getDeclaredFields/Methods/Constructors`、`Field.get/set`、`Method.invoke`、
  `getAnnotation` 一族、`getParameters0`（真读 `MethodParameters` 属性）
- **线程与监视器**：每 Java 线程一个 OS 线程、无全局锁（真并行）、`monitorenter/exit` 可重入、
  `LockSupport.park` 带许可、`ReentrantLock` / `CountDownLatch` / `Semaphore` 已通
- **JNI**：`JNINativeInterface_` 236 槽位里 196 条真实现，含 `RegisterNatives`、回调进 Java、
  `ThrowNew`、字符串/数组往返（中文）
- **`invokedynamic`**：调用点缓存、`LambdaMetafactory`、`StringConcatFactory`、`MethodHandles` 构造族

## 不能用的 / 已知短板

### 语言层（自研 javac）
剩 26.1% 编不过（805 个编译失败 + 79 个解析失败），按新桶表：

| 桶 | 次数 | 说明 |
| --- | --- | --- |
| 未定义的变量 | 137 | 第一名是**局部类**（`void m(){ class Holder{...} }` —— parser 把方法体里的类声明整段丢掉） |
| 未找到实例方法 | 127 | 长尾，单个名字 ≤11 次 |
| 未找到方法 | 86 | 同上 |
| 块体 lambda | 49 | parser 把 `{ … }` 体塞进占位节点 |
| **比较结果作为表达式** | 32 + 22 | 受**帧模型**限制：`bool_from_branch` 硬要求跳转点栈为空 |
| parse 各类 | 79 | `期望标识符，实际 X` 为主（compact constructor、record 模式） |
| 类型转换 | 21 + 15 | — |

两条**结构性**缺口（不是补几条语法能解决的）：

1. **局部变量帧没有按路径合并** —— `Emit::stack_map` 一律「栈为 0 + locals 按当前累积表」写帧，
   循环回边上的 locals 没做合并。后果是产出**不可验证的 class**（`javap` 能读，真 JVM `-Xverify:all` 拒载）。
   真 JVM 抽样里 9 个 class 有 1 个因此装载失败。
2. **访问修饰符一律写成 public** —— 成员名与描述符与真 javac 逐个一致，但修饰符不对（既有偏差）。

### 运行时
- **`Condition.await/signal` 仍挂**。`ReentrantLock` / `CountDownLatch` / `Semaphore` 已通，
  同一个 AQS 家族的这一条还差：要查 `ConditionObject` 的 `fullyRelease` + `park` + 重入恢复顺序。
- **`Thread.getStackTrace` / `StackWalker` 给不出帧** —— 本 VM 没有帧栈模型（`Vm` 只有 `depth` 计数）。
  这是**必须补的部件**，不是可选：没有栈就没法定位死锁，也没法实现 `jstack` 的 Java 侧。
- **`Continuation` / 虚拟线程**：虚拟线程用平台线程顶（语义等价、性能可接受），`Continuation` 明确抛 UOE。
- **FFM（`java.lang.foreign`）**：没有 libffi，`LibFallback.doDowncall` 明确报错。
- **`drawString`**：JDK 25 走 HarfBuzz/FFM，卡在 `jdk.internal.foreign.Utils.<clinit>`；
  `DrawGlyphList*` 现在显式抛异常。真窗口（`WToolkit`/`WComponentPeer`）代码写了但**起不来**。
- **WatchService / Selector**：native 有了，但依赖上面「先阻塞再等事件」的路径，未端到端验证。
- **`AWT` 初始化后进程退出会挂**（`Toolkit.getDefaultToolkit()` 之后）。

### 明确没做
- `FileDispatcherImpl.map0` / `transferTo0`（内存映射文件）—— 明确抛 `IOException`，不装能跑
- `CDS` 归档 dump、`Perf` attach/create（无 `hsperfdata`）、`ThreadSnapshot`（无 JFR 集成）
- 句柄复用 + epoch：句柄是 `i32` 且四种语义已占满，要复用必须改宽（`i64 = index32 + epoch32`）

## 已知的坑（踩过的，别再踩）

按「症状 → 根因」记，因为这些症状都很容易误判：

| 症状 | 根因 |
| --- | --- |
| 程序卡死、有 CPU、无输出 | `waitForReferencePendingList` 是 `no_op`，`ReferenceHandler` 死循环 |
| 建到**第 3 个** `ThreadLocal` 时卡死 | `get_mem` 符号扩展 vs `weakCompareAndSetInt` 零扩展 → CAS 恒 false → `getAndAddInt` 永不收敛 |
| 所有 `Files.*` 报「文件名语法不正确」 | `copyMemory` 未按元素宽度换算（`char[]` 每字符低字节写两遍 → `D:\x` 变 `DD::\\xx`） |
| 同一路径第一次 `FILE_NOT_FOUND`、重试又好 | `read_wstr` 没把 NUL 带回去，Win32 读到缓冲区垃圾 |
| `new FileInputStream(...)` 构造器全部失败 | `Thread$FieldHolder.group` 为 null → `Cleaner` 拿它 `synchronized` 就 NPE |
| `System.out/err/in` 恒 null | `ReflectionFactory.<clinit>` 没先跑，`JavaLangReflectAccess.getRoot` 空接收者 |
| `ClassLoader.registerAsParallelCapable` 抛 `IllegalCallerException` | `Reflection.getCallerClass` 缺失，返回 `java.lang.Object` |
| 非 ASCII 字符串全乱码（ASCII 正常） | `StringUTF16` 用的是**小端**存 UTF-16，不是大端 |
| `add_override` 注册了但永远不被调用 | `exec.rs::is_override_owner` 是**白名单**，类名不在里面就是死代码 |
| 有 classpath 正常、独立模式编不过 | 内建表兜底被「存在才返回」的 owner 短路 |
| 通过率突然掉一大截（40% vs 62%） | `cover_dir` 的 `platform()` 整个进程只反解一次 classpath，一个 `.class` 读失败就静默当「类不存在」→ **先重跑** |
| 带外文件监视器锁住刚跑过的 exe（LNK1104 / Device or resource busy） | 覆盖会**静默失败**（cp 失败但你跑的是旧 exe）→ 每轮复制到新目录再跑，target 目录轮换 |
