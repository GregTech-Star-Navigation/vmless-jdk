# 工具退出码约定与矩阵

> 状态：2026-11-18 实测（Windows Server，vmless 工具集 `jdk-tools` 0.1.1）
> 复跑：`bash scripts/tool-audit.sh`（15 工具 × 8 类坏输入）+ `cargo test --test bad_inputs`（6 类，进 CI）

## 1 三个退出码，各管一类事

| 码 | 含义 | 典型场景 | 输出到 |
| ---: | --- | --- | --- |
| `0` | 成功 | 干完了（哪怕是「加载 0 个类」这种空结果） | stdout 打结果 |
| `1` | **运行错** | 文件不存在、格式坏、校验失败、端口被占、权限不足 | stderr 打 `工具名: 原因` |
| `2` | **用法错** | 不认识的选项、选项缺值、缺动作、动作非法、端口不是数字 | stderr 打 `工具名: 原因` + `使用 X --help 查看用法` |

设计取舍：真 JDK 对用法错也用 `1`（`java -badopt` 返回 1），我们固定用 `2`，
这样脚本能区分「我传错了」和「东西坏了」—— 这是**刻意的偏离**，写在 `jdk-tools/src/lib.rs` 里。

**硬红线：任何输入都不许 panic。** 所有对外入口返回 `Result<_, String>`，
错误在 bin 层统一转成 `eprintln!` + 退出码，不存在 `unwrap()` 崩栈的路径。
这条由 `cargo test --test bad_inputs` 的三条断言守住（非 0 / stderr 非空 / 无 `panicked at` 且退出码不是 101）。

## 3 八类坏输入，逐类怎么判

| 坏输入 | 期望 | 实测 |
| --- | --- | --- |
| 不存在的路径 | 1 + 指明路径 | 15/15 工具都报 `打开 … 失败: 系统找不到指定的路径` 一类的话 |
| 空文件 | 1（数据格式工具）/ 0（脚本类工具） | `jimage`/`jmod`/`serialver`/`jdb` 等 → 1；`jshell`/`javadoc`/`jrunscript` → 0（空输入合法） |
| 截断文件 | 1 + 说明「截断/不完整」 | 全部 1，且消息点出问题（如 `的索引区声称 155… 但文件只有 2048 字节（被截断的 jimage）`） |
| 只读目录 | 1 + 写失败原因 | `jimage extract` / `jmod create` / `jlink --output` / `javadoc -d` 全部 1 |
| 超长路径（>260 字符） | 1 + 不崩溃 | 全部 1（Windows 下是「路径不存在」或「文件名太长」） |
| 非法选项 | 2 + 提示看 help | 15/15 都是 2 |
| 权限不足（ACL deny） | 1 + `拒绝访问` | `jimage`/`jmod`/`serialver`/`jwebserver` 实测 1 |
| 端口占用 | 1 + `监听 … 失败` | `jwebserver`（同址冲突）1；`rmiregistry` 1 |

## 4 特例与已知边界（读矩阵前先看这里）

1. **`jps` 忽略位置参数。** `jps -l <不存在的东西>` 返回 0、stderr 为空 —— 位置参数被当成 hostid 忽略掉了。
   真 `jps` 会去解析 hostid 并报通信错误。我们不做远程查询，所以静默忽略。
   **这是有意保留的**（改成报错会让 `jps -l $(hostname)` 这类常见脚本直接红），已记录在案。
2. **`rmiregistry` / `jwebserver` 是常驻服务**：正常启动就不会退出。用 `timeout` 跑会得到 124，
   那不是错误，是「它在正常服务」。测它们的错误路径只能靠**让它们起不来**（端口占用、目录不存在）。
3. **Windows 的端口复用语义**：一个 socket 绑 `0.0.0.0:P` 之后，另一个绑 `127.0.0.1:P` 仍可能成功
   （`SO_REUSEADDR`，Java 默认也这样）。所以「端口占用」用例要把两边绑到**同一个地址**才稳定复现 1。
4. **`javaw` 是 GUI 子系统**：控制台里 `stderr` 是空的，只能靠退出码判断。这是 Windows 的平台行为，不是缺陷。
5. **空输入不是错误**：`jshell empty.jsh` / `javadoc Empty.java` / `jrunscript empty.js` 返回 0。
   数据格式工具（`jimage`/`jmod`）则相反：空文件一律 1。
6. **`jlink` 要模块目录，不要 `lib/modules` 镜像**：传镜像会明确报
   `里没有 module-info.class —— 它不是一个模块`（1）。传解包出来的模块目录则成功
   （实测 java.base 一个模块、7397 个条目、29.9 MB，产出 95 MB 镜像）。
