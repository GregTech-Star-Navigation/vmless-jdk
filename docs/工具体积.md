## 为什么 jdb / jshell 是别人的两倍

不是「代码写得多」，是**静态链接的模块多**。这三个体积档位很干净地对应三组依赖：

| 档位 | 体积 | 链接了什么 | 哪些工具 |
| --- | ---: | --- | --- |
| 只读字节码/容器 | 144–400 KB | 只 `classfile` 的解析部分（class/zip/jimage） | `jimage` `jmod` `serialver` `jnativescan` `jdeprscan` `jlink` `jwebserver` `jps` `rmiregistry` `jpackage` 与全部 shim |
| 带解释器 | ~1.4 MB | + `classfile::vm` | `javaw` |
| 带编译器 | ~2.2 MB | + `classfile::parser` + `classfile::compiler`（前端 + 代码生成） | `jshell` `jdb` |

想变小有两条现成的路（都**没做**，因为不是当前问题）：

- `Cargo.toml` 加 `[profile.release] lto = "fat"` + `codegen-units = 1`：通常能掉 20~35%，代价是构建慢几倍；
- `strip = true` 去掉符号表（现在 release 默认已不带 debug info，收益有限）。
